- 脚本统一采用 Node ESM（`.mjs`），通过 `fileURLToPath(new URL('..', import.meta.url))` 解析仓库根路径，再拼接 `packages/*/...` 目标。
- 示例目录校验逻辑集中在 `example-catalog-lib.mjs` 中以纯函数形式导出（如 `validateExampleCatalog`、`discoverExampleUnits`），其他脚本仅做参数组装与错误输出。
- 白名单式校验：所有允许的 section、goal、capability、format、level、entry key 均以常量 Set 声明，校验时逐一比对而非正则兜底。
- 路径安全校验统一通过 `isSafeRelativePath` 拒绝绝对路径、`..` 片段、反斜杠与非 posix 规范化路径，防止目录穿越。
- CI 中的性能门控采用宽松阈值（10x RFC 微秒预算、<1000% 同机开销）并在失败时汇总为可读的错误列表抛出。
- GitHub Actions job 普遍使用 `actions/setup-node@v4` + `cache: npm` 缓存依赖，并通过 `timeout-minutes: 15` 限制单任务时长。
