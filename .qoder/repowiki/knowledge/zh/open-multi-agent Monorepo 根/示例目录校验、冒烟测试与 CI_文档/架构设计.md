模块由三个并列子目录组成，职责清晰且无相互依赖：
- `scripts/`：基于 Node ESM（`.mjs`）的纯脚本集合，核心是 `example-catalog-lib.mjs`，集中定义示例清单的 schema（`CATALOG_SCHEMA_VERSION`、`EXAMPLE_SECTIONS`、`EXAMPLE_CAPABILITIES`、`ENTRY_KEYS` 等白名单），并提供 `discoverExampleUnits`、`validateCatalogDocument`、`validateExampleCatalog`、`readCatalog` 等导出函数；其余脚本均为薄包装入口——`validate-example-catalog.mjs` 读取 `packages/core/examples/catalog.json` 并调用校验库；`eval-example-smoke.mjs`、`observability-example-smoke.mjs`、`observability-tarball-smoke.mjs` 通过 `child_process.spawn` 以独立进程运行对应示例或 tarball；`observability-benchmark-ci.mjs` 执行 `packages/core/benchmarks/observability-sinks.mjs` 并以宽松阈值（10x RFC 预算）做 CI gate；`example-catalog.test.mjs` 用该库对 catalog 做断言。
- `.github/workflows/`：`ci.yml` 串联 lint、test（Node 20/22/24 矩阵）、coverage（Codecov OIDC）、package（验证 npm tarball 文件集、CLI help、eval gate pass/fail、create-oma-app 模板版本锁定、otel 入口导入）、scaffold-e2e 等 job；`provider-canary.yml`、`release-smoke.yml` 分别用于 provider 灰度与发布冒烟。
- `docs/`：按主题组织的 Markdown 文档（adaptive-recovery、checkpoint、cli、consensus、context-management、durable-approvals、evaluation、execution-routing、external-agents、featured-partner、model-routing、observability*、plan-replay、providers、shared-memory、structured-input、task-scheduling、tool-configuration），作为用户与贡献者参考。
依赖方向单向：CI → scripts → packages/*，scripts 不反向引用业务代码，仅通过 `child_process` 启动已构建产物。
